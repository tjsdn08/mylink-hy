# MyLink 최종 기능 테스트

> 테스트 결과가 체크되지 않았다면 **미검증**입니다. 이 체크리스트는 실행 결과가 아니라 검증 절차입니다. 기획과 구현의 차이는 [PRODUCT_ALIGNMENT.md](PRODUCT_ALIGNMENT.md)에 기록합니다.

## 기획·디자인·개발 연결 최종 점검

- [ ] 로그인 직후 username이 없는 신규 사용자가 **온보딩 화면**에 진입하고 관리 화면으로 바로 넘어가지 못하는지 확인
- [ ] username과 표시 이름 저장 후 공개 주소가 생성되고 새로고침해도 유지되는지 확인
- [ ] `/links` 접근 시 샘플 링크가 노출되지 않고 `/`로 이동하는지 확인
- [ ] 링크 새로 추가/수정 중 저장 전 미리보기 반영, 취소 후 복원, 저장 후 비로그인 공개 화면의 일치 확인
- [ ] 비활성 링크의 카운터를 비로그인 클라이언트에서 직접 +1 요청할 때 Firestore 규칙이 거부하는지 확인 (최신 규칙 게시 이후)
- [ ] **최신 Firestore 규칙 게시 후** 비로그인 사용자의 비활성 링크 직접 읽기가 거부되고 활성 링크 목록만 조회되는지 확인
- [ ] 신규 기능(SNS 정렬·탈퇴·온보딩)이 실제 검증 전에는 완전한 운영 기능으로 소개되지 않는지 확인. 사진 업로드는 Spark 범위에서 제외
- [ ] 랜딩·온보딩·관리 미리보기가 공통 휴대폰 프레임(모바일 460px / sm 이상 520px)과 내부 스크롤을 사용하고, 화면이 잘리거나 미리보기 전체 길이만큼 부모 페이지가 늘어나지 않는지 확인
- [ ] 계정 메뉴에 ‘내 공개 페이지’만 남고 같은 공개 페이지를 여는 중복 ‘내 프로필 미리보기’가 제거됐는지 확인
- [ ] 편집 미리보기는 저장 전 변경 내용을 보여주고, 별도 ‘실제 공개 페이지’ 링크는 저장된 콘텐츠만 표시하는지 확인
- [ ] 랜딩·관리·공개 프로필이 크림·라임·차콜·코랄 제품 디자인과 공통 프로필 컴포넌트를 사용하는지 확인
- [ ] 모바일 320px/375px에서 상단 CTA, 관리 폼, 공개 프로필에 가로 스크롤이나 텍스트 겹침이 없는지 확인
- [ ] 통계의 조회 수는 고유 방문자가 아니며 중복·봇 요청이 포함될 수 있다고 안내하는지 확인


## 신규 구현 기능 수용 테스트

- [ ] 계정 A 최초 Google 로그인 → 필수 username/표시 이름 설정 → 대시보드 → 편집 화면 이동
- [ ] 계정 A가 이미 사용 중인 Username, 예약어(`dashboard`, `stats`)를 등록할 수 없는지 확인
- [ ] `/dashboard`의 링크·조회 카드에 실제 계정 데이터 표시, 카드 클릭 시 해당 `/mypage?tab=` 탭 열림
- [ ] 로그인 상태 `/`은 대시보드, 비로그인 상태 `/`은 랜딩을 표시
- [ ] Google 계정 프로필 사진이 마이페이지·공개 페이지에 표시되고, 사진 업로드 버튼이 없는지 확인
- [ ] 프로필 이미지 5MB 초과 또는 허용하지 않는 형식 거부
- [ ] 테마·배경·버튼·글자색 변경 후 미리보기/저장/비로그인 공개 페이지 확인
- [ ] SNS 아이콘 순서 드래그 및 위·아래 버튼으로 조정 후 새로고침해도 순서 유지
- [ ] SNS URL을 저장하지 않은 상태에서 순서만 옮겼을 때 변경하지 않은 URL은 공개되지 않는지 확인
- [ ] 링크 신규 등록 폼에 제목·유효 URL 입력 시 미리보기 노출, 폼 취소 시 제거
- [ ] 기존 링크 편집 중 제목·설명·대표 여부를 수정하면 미리보기에 반영, 취소 시 원복
- [ ] Firestore Rules 게시 후 소유자와 비로그인 방문자의 활성/비활성 링크 읽기 권한 구분
- [ ] 구형 링크에 `isActive`가 빠져 있다면 소유자 로그인 후 `true`로 자동 보완되는지 확인
- [ ] **테스트 계정**으로 계정 탈퇴: 확인 문구와 Google 재인증, Firestore 링크·프로필·username 및 Firebase Auth 삭제 확인 (Google 계정 사진 자체는 유지)
- [ ] 탈퇴 후 비로그인 공개 URL 접근이 불가능하고 해당 username을 다시 등록할 수 있는지 확인
- [ ] 탈퇴 도중 권한/네트워크 실패 시 오류 안내와 재시도 가능 여부 확인 (브라우저 기반 삭제는 원자적이지 않음)
- [ ] Firestore 규칙만 Firebase Console에 게시했는지 확인 (Cloud Storage 규칙 게시 불필요)

**실행 환경**: Chrome 데스크톱 / Chrome 모바일 또는 기기 개발자 도구 / Firebase 테스트 계정 A·B

**주의**: 이 문서는 테스트 절차이며 체크박스는 아직 실행 완료를 뜻하지 않습니다. Firestore 규칙 배포와 실제 Firebase 계정 테스트는 별도로 수행해야 합니다.

## 추가 기능 테스트

- [ ] 프로필 디자인: 테마 크림·라벤더·미드나잇 선택 후 저장, 새로고침해도 유지
- [ ] 배경색 선택 및 버튼 모양 둥근형·캡슐형·각진형 반영
- [ ] SNS URL 등록·삭제 후 공개 프로필 아이콘 반영
- [ ] 링크 설명 및 썸네일 URL 편집 후 표시 확인
- [ ] 대표 링크 설정 시 공개 카드 강조 및 썸네일 표시 확인
- [ ] 링크 비공개 시 공개 페이지 목록에서 제외되고, 재공개하면 복귀
- [ ] 링크 드래그 또는 위·아래 버튼으로 변경한 순서가 새로고침 후 유지
- [ ] Firestore 규칙 게시 후 비로그인 공개 프로필 조회 수 1 증가
- [ ] 통계 화면에 방문 수와 방문당 클릭 수가 표시되는지 확인
- [ ] 크림·라벤더·미드나잇 세 테마의 링크 카드 텍스트 대비 확인
- [ ] 모든 화면에서 브랜드 색상 일관성 확인 및 모바일 너비 320px·375px 확인

**보안 범위:** 현재 비공개 링크는 UI에서만 숨겨지고 Firestore 원본 링크가 비밀 처리되는 기능은 아닙니다.

## 편집 UX 및 QR 최종 점검

- [ ] 링크 관리 / 프로필 / 디자인·SNS 탭 전환 시 입력 화면과 오른쪽 미리보기 동작
- [ ] 디자인 편집 화면에서 테마·배경색·버튼 모양을 바꾼 뒤 미리보기 반영, 저장 전 공개 페이지는 그대로 유지
- [ ] 이름·소개글 인라인 수정, 취소 및 Esc 취소, 저장 후 새로고침 데이터 유지
- [ ] 링크 생성·수정 시 `github.com` 입력하면 `https://github.com`으로 보완, 위험한 URL은 저장 거부
- [ ] 프로젝트·SNS 등 링크 그룹을 설정하고 공개 페이지에서 그룹 제목으로 분리 표시
- [ ] 그룹 없는 기존 링크도 정상 표시, 링크 숨김·대표 설정·클릭 집계 유지
- [ ] 공개 페이지 QR 버튼으로 표시 및 주소 복사, 닫기·Esc 동작
- [ ] QR 생성 서비스가 응답하지 않을 때에도 공개 페이지의 나머지 기능이 정상 동작
- [ ] 동작 줄이기 설정(prefers-reduced-motion)에서 링크 등장 효과 비활성화
- [ ] GitHub Actions Verify MyLink 검사 전부 통과 및 Vercel 배포 성공

## 개인화 화면 일관성 검증

- [ ] 랜딩의 휴대폰 예시와 마이페이지 미리보기의 프레임·프로필 헤더·카드 배치가 같은지 확인
- [ ] 크림/라벤더/미드나잇 테마별로 커버 서클/그리드/미니멀 패턴 선택 후 저장·재접속 확인
- [ ] 한 줄 소개, About me, 요즘 하고 있는 일 저장 및 공개 프로필 반영 확인
- [ ] 새 항목이 비어 있으면 공개 프로필에서 해당 카드가 숨겨지는지 확인
- [ ] 이전에 등록한 그룹 없는 링크가 카테고리 섹션 아래에 표시되는지 확인
- [ ] 대표 링크가 별도 상단 영역에 표시되고 링크 클릭 수가 계속 집계되는지 확인
- [ ] 마이페이지의 개인화 안내 숫자가 데이터 저장 후 증가하는지 확인
- [ ] 작은 모바일 화면 및 다크 모드에서 프로필 카드 텍스트 대비와 가로 스크롤 확인
- [ ] 최신 `firestore.rules` 게시 후 개인화 저장 권한 검사
