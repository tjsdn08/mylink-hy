# MyLink 텍스트 와이어프레임 (WIREFRAMES)

> **목표 화면·정보 구조의 설계 기록**입니다. 현재 탭형 관리 UI와 경로는 [제품 통합 기준](PRODUCT_ALIGNMENT.md)에서 확인하세요. 디자인 방향은 초기 화이트·블루 레퍼런스에서 크림·라임 기반 MyLink 제품 UI로 발전했으며, 기존 와이어프레임의 경로는 모두 실제 서비스 URL을 뜻하지 않습니다.

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 프로젝트 | MyLink |
| 문서 유형 | Text Wireframes |
| 기준 문서 | PRD.md, USER_SCENARIOS.md |
| 최종 목표 | Phase 1~3 전체 기능 구현 |
| 디자인 방향 | 현재 MyLink 크림·라임·차콜·코랄 UI, Toss는 UX 참고 |
| 화면 지원 | 모바일·태블릿·데스크톱 |

### 1.1 설계 목적

MyLink의 전체 화면 구조와 사용자의 이동 흐름을 정의한다.

본 문서는 실제 UI를 개발하기 전 각 페이지의 구성 요소, 버튼, 입력 폼, 상태 표시, 화면 간 이동을 확인하기 위한 설계 자료다.

### 1.2 디자인 원칙

- 간결하고 직관적인 인터페이스
- 크림 기반 바탕, 라임 강조색, 차콜 글자, 코랄 보조색
- 충분한 여백 및 일관된 간격
- 명확한 버튼과 입력 폼
- 사용자가 수행할 작업을 중심으로 화면 구성
- 반응형 레이아웃
- 모바일 터치 조작 지원
- 접근 가능한 색상 대비와 키보드 탐색 고려

Toss의 전반적인 사용성 및 시각적 특성을 참고하지만 공식 디자인 자산을 복제하지 않는다.

## 2. 전체 사이트맵

```text
MyLink
│
├── 비로그인 영역
│   ├── 랜딩 페이지 (/)
│   ├── 로그인 (/login)
│   └── 공개 프로필 (/:username)
│
├── 최초 가입
│   └── 온보딩 (/onboarding)
│
└── 로그인 사용자 관리 영역
    ├── 대시보드 (/dashboard)
    ├── 프로필 관리 (/dashboard/profile)
    ├── 링크 관리 (/dashboard/links)
    │   ├── 일반 링크 등록/수정
    │   └── SNS 링크 등록/수정
    ├── 디자인 설정 (/dashboard/design)
    ├── 통계 (/dashboard/stats)
    └── 계정 설정 (/dashboard/settings)
        ├── Username 변경
        └── 계정 탈퇴
```

위 경로는 권장 라우팅 구조이며 실제 Next.js App Router 및 예약어 정책에 맞춰 구현한다.

공통 요소:

- 현재 메뉴 강조
- 페이지 제목 및 설명
- 주요 액션 버튼

- 입력 폼과 버튼 터치 영역 확보
- 가로 스크롤 최소화

### 입력 규칙

Username:
- 필수
- 3~20자
- 영문 소문자, 숫자, 밑줄 허용
- 중복 불가
- 예약 경로 사용 불가

표시 이름:
- 필수

프로필 사진:
- 선택
- JPG, PNG, WebP
- 최대 5MB

자기소개:
- 선택

### 동작

- Username 입력값 검증
- 중복 여부 확인
- 필수값이 없으면 완료 버튼 비활성화 또는 제출 시 검증 오류
- 등록 완료 시 대시보드 이동

공개 URL의 도메인은 실제 배포 후 확정한다.

## WF-06. 일반 링크 관리

**경로:** `/dashboard/links`  
**개발 단계:** Phase 1, 순서 및 활성화는 Phase 2

```text

│                                                           │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ ≡  포트폴리오                    [ON] [편집] [삭제]   │ │
│ │    https://example.com                               │ │
│ ├───────────────────────────────────────────────────────┤ │
│ │ ≡  GitHub                        [ON] [편집] [삭제]   │ │
│ │    https://github.com/...                            │ │

│ │ ≡  블로그                        [OFF] [편집] [삭제]  │ │
│ │    https://blog.example.com                          │ │
│ └───────────────────────────────────────────────────────┘ │
│                                                           │
│                                     ┌───────────────────┐ │
│                                     │     미리보기      │ │
```

### 주요 요소

- 일반 링크 / SNS 아이콘 전환
- 링크 추가 버튼
- 링크 제목
- URL
- 이미지 또는 아이콘
- 활성화 스위치
- 편집 버튼
- 삭제 버튼
- 드래그 핸들
- 미리보기

### 동작

- 추가/수정은 저장 버튼으로 반영
- 삭제는 확인 모달을 거쳐 영구 삭제
- 활성화 변경은 상태를 저장하고 공개 페이지에 반영
- 드래그 완료 시 순서 자동 저장
- 비활성화 링크는 공개 페이지에 표시하지 않음

### 단계 구분

Phase 1:
- 링크 CRUD

Phase 2:
- 드래그 정렬
- 활성화
- SNS 관리
- 미리보기

- 사용자 프로필을 그대로 표시
- 빈 영역에 적절한 안내 제공
- 방문자에게 관리 기능을 요구하지 않음

## 8. UX 및 접근성 기준

### 입력 폼

- 필수 항목 표시
- 입력 오류 위치 안내
- 저장 중 중복 제출 방지
- 저장 실패 시 입력값 유지

### 삭제 모달

- 삭제 대상 명확히 표시
- 복구 불가 안내
- 취소와 삭제 버튼 구분
- 키보드 및 포커스 제어

### 링크 정렬

- 드래그 가능한 영역 명확히 표시
- 모바일 터치 지원
- 저장 완료 및 실패 피드백
- 가능한 범위에서 키보드 정렬 대안 고려

### 테마

- 색상 변경 실시간 미리보기
- 저장 전 공개 데이터 유지
- 가독성을 고려한 색상 대비

### 외부 링크

- 새 탭 열기
- 안전한 rel 속성
- 링크 제목으로 목적지 식별 가능

## 10. 최종 개발 검증 체크리스트

- [ ] 신규 사용자가 Google 로그인 후 온보딩에 진입한다.
- [ ] username 중복 및 형식 검증이 작동한다.
- [ ] 기존 사용자는 대시보드로 이동한다.
- [ ] 프로필을 등록하고 수정할 수 있다.
- [ ] 일반 링크를 추가·조회·수정·삭제할 수 있다.
- [ ] 링크 삭제 시 확인 모달이 표시된다.
- [ ] 일반 링크 순서를 변경할 수 있다.
- [ ] 변경된 순서가 자동 저장된다.
- [ ] 링크 활성화 상태가 공개 페이지에 반영된다.
- [ ] SNS 플랫폼을 선택해 URL을 등록할 수 있다.
- [ ] SNS 아이콘이 올바르게 표시된다.
- [ ] SNS 아이콘 순서를 변경할 수 있다.
- [ ] 기본 테마와 색상을 변경할 수 있다.
- [ ] 저장 전 실시간 미리보기가 작동한다.
- [ ] 저장 전 변경 내용이 공개 페이지에 노출되지 않는다.
- [ ] 비로그인 방문자가 공개 프로필에 접근할 수 있다.
- [ ] 모든 외부 링크가 새 탭에서 열린다.
- [ ] URL 복사 및 공유가 작동한다.
- [ ] 링크별·전체 클릭 통계가 표시된다.
- [ ] 비활성 링크의 기존 클릭 통계가 보존된다.
- [ ] 개인별 OG 미리보기가 제공된다.
- [ ] username을 변경할 수 있다.
- [ ] 계정 탈퇴 시 관련 데이터가 삭제된다.
- [ ] 다른 사용자의 데이터에 접근하거나 수정할 수 없다.
- [ ] 모바일·태블릿·데스크톱에서 정상 표시된다.
- [ ] Vercel 배포 URL에서 주요 기능이 정상 동작한다.

## 11. 문서 간 관계

- `PRD.md`: 무엇을 구현할 것인가?
- `USER_SCENARIOS.md`: 사용자는 어떻게 기능을 이용하는가?
- `WIREFRAMES.md`: 화면을 어떻게 구성하고 연결할 것인가?

세 문서는 MyLink의 최종 기획 기준이며, 구현 중 설계 변경이 필요하다면 문서 간 일관성을 유지해야 한다.
