# MyLink 제품 요구사항 정의서 (PRD)

> **이 문서는 목표 요구사항 정의서입니다.** 실제 구현 현황과 미구현 항목은 [제품·디자인·개발 통합 기준](PRODUCT_ALIGNMENT.md)을 함께 확인합니다. 코드에 없다는 이유로 확정 요구사항을 제거하지 않습니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | MyLink |
| 서비스 유형 | Linktree와 유사한 개인 링크 모음 서비스 |
| 대상 사용자 | 일반 사용자, 크리에이터, 개발자, 구직자 등 누구나 |
| 개발 방식 | 단계별 구현 |
| 최종 목표 | 1~3단계 전체 기능 완성 |
| GitHub | https://github.com/tjsdn08/mylink-hy |
| 배포 | Vercel 무료 플랜 |
| UI 스타일 | MyLink 크림·라임·차콜·코랄 브랜드 UI (Toss는 사용성 참고) |

### 1.1 서비스 소개

MyLink는 사용자가 자신만의 프로필 페이지를 만들고 여러 웹사이트와 SNS 링크를 하나의 URL로 공유할 수 있는 웹 서비스다.

사용자는 Google 계정으로 로그인해 프로필, 일반 링크, SNS 링크, 디자인을 관리할 수 있다.

방문자는 로그인 없이 공개 프로필을 열람하고 링크를 클릭하거나 페이지를 공유할 수 있다.

### 1.2 핵심 목표

- 하나의 URL로 여러 링크 공유
- 간편한 Google 로그인
- 사용자별 고유 프로필 주소
- 일반 링크 CRUD
- SNS 아이콘 관리
- 프로필 및 디자인 커스터마이징
- 링크 순서 변경
- 클릭 통계 확인
- 반응형 UI
- Firebase 기반 데이터 저장 및 보안
- Vercel 배포

## 2. 기술 스택

| 구분 | 기술 |
|---|---|
| Framework | Next.js 16 |
| UI | React 19 |
| UI Component System | shadcn/ui |
| Language | TypeScript 5 |
| Styling | Tailwind CSS v4.3.5 (shadcn/ui 호환 안정 버전) |
| Design Guidelines | `design.md` 기반 Toss 스타일 디자인 시스템 |
| State Management | React state/Context + Firestore 실시간 구독 (현 구현); Zustand는 미사용 |
| Authentication | Firebase Authentication |
| Database | Cloud Firestore |
| File Storage | Firebase Storage (프로필 이미지 직접 업로드 목표, 미구현) |
| Hosting | Vercel |
| Version Control | Git / GitHub |

### 2.1 상태 관리 정책

- **React useState**: 현재 프로필·링크·테마 편집 상태 (Zustand 도입은 확정되지 않은 미래 선택지)
- **Firebase Auth + React Context**: 사용자 인증 상태
- **Cloud Firestore**: 서버 데이터의 기준 저장소
- **React useState**: 단일 컴포넌트의 간단한 폼 상태

Firestore를 데이터의 기준 저장소로 유지한다. 추후 전역 상태관리 도구를 도입하더라도 서버 데이터를 무분별하게 중복 저장하지 않는다.

기존 프로젝트의 실제 설치 버전과 구조를 먼저 확인한 후 개발한다.

### 2.2 디자인 시스템 정책

1. 모든 신규 UI는 shadcn/ui를 기반으로 개발한다.
2. 시각적 디자인과 UX 기준은 기존 `design.md`를 따른다.
3. shadcn/ui 컴포넌트는 재사용 가능한 형태로 구성한다.
4. 컬러, 타이포그래피, 간격, 모서리 등은 일관된 디자인 토큰으로 관리한다.
5. 제품 브랜드는 크림·라임·차콜·코랄을 유지한다. 초기 화이트·블루 Toss 시안은 레퍼런스로만 사용한다.
6. 모바일·태블릿·데스크톱 반응형 디자인을 지원한다.
7. 접근성과 사용성을 고려해 UI를 구현한다.
8. 새 페이지와 기능에도 동일한 디자인 시스템을 적용한다.
9. 현재 제품의 디자인 기준은 `src/app/globals.css` 및 `src/lib/profile-design.ts`와 공통 컴포넌트다. `design.md`는 초기 Toss 연구 레퍼런스다.

초기화 현황과 향후 구현 범위:
- 현재 단계에서 shadcn/ui CLI 초기화, `components.json`, CSS 변수 기반 테마 설정, TypeScript 경로 별칭 및 필수 의존성 구성을 완료한다.
- Tailwind CSS 및 기존 Turbopack 통합은 shadcn/ui와 호환되는 안정 버전을 사용한다.
- 초기화 완료는 실제 화면이나 디자인 시스템 컴포넌트 적용 완료를 의미하지 않는다. 화면별 적용, 디자인 토큰 세부 조정 및 추가 컴포넌트 구현은 후속 개발 단계에서 진행한다.
- 이번 단계에서는 기존 프로필 화면의 UI를 변경하지 않는다.

## 4. 인증 및 회원가입

### FR-01. Google 로그인

- Firebase Authentication 사용
- Google 소셜 로그인만 제공
- 별도 이메일·비밀번호 회원가입 기능 없음
- 로그인 성공 시 사용자 인증 상태 확인
- 로그아웃 기능 제공
- 비로그인 사용자가 관리 페이지에 접근하면 로그인 화면으로 이동

### FR-02. 최초 온보딩

최초 로그인 시 필수 입력:
- 고유 아이디(username)
- 표시 이름(displayName)

선택 입력:
- 프로필 사진
- 자기소개
- 기본 테마 및 색상

필수 정보 입력을 완료해야 대시보드에 진입할 수 있다.

기존 사용자는 로그인 후 온보딩을 반복하지 않고 대시보드로 이동한다.

## 5. 고유 아이디 및 공개 URL

### FR-03. Username 규칙

- 길이: 3~20자
- 허용 문자: 영문 소문자(a-z), 숫자(0-9), 밑줄(_)
- 중복 아이디 사용 불가
- 가입 시 사용자가 직접 설정
- 가입 이후 자유롭게 변경 가능
- 변경 전 새 username의 사용 가능 여부 확인

공개 주소 형식:

`https://배포도메인/username`

예시:

`https://mylink-hy.vercel.app/sunwoo_08`

위 주소는 형식 예시이며 실제 배포 주소는 배포 완료 후 확정한다.

### FR-04. Username 변경 및 재사용

- 사용자가 username을 변경하면 기존 URL은 즉시 비활성화
- 이전 username은 다른 사용자가 즉시 사용 가능
- 계정 탈퇴 후에도 username 즉시 재사용 가능
- username 중복 등록은 원자적 처리로 방지
- 기존에 공유된 주소가 새로운 소유자에게 연결될 수 있다는 위험 안내

다음과 같은 시스템 예약 경로는 username으로 사용할 수 없다.

예시:
- login
- dashboard
- onboarding
- api
- settings

실제 예약어 목록은 라우팅 구조에 맞춰 정의한다.

## 6. 프로필 관리

### FR-05. 프로필 편집

사용자는 다음 정보를 수정할 수 있다.

- 프로필 사진
- 표시 이름
- 자기소개

편집 정책:
- 입력 중 실시간 미리보기 제공
- 저장 버튼을 눌러야 실제 공개 페이지에 반영
- 저장 성공 시 완료 메시지 표시
- 저장 실패 시 입력값 유지 및 오류 표시

### FR-06. 프로필 이미지

지원 형식:
- JPG
- PNG
- WebP

제약:
- 최대 5MB
- Firebase Storage 저장
- 정사각형 영역에 표시
- 이미지 비율 왜곡 방지
- 이미지 크롭 편집 기능은 제공하지 않음

클라이언트와 Firebase Storage 보안 규칙에서 파일 형식, 용량, 소유권을 검증한다.

## 7. 일반 링크 관리

### FR-07. 링크 CRUD

필수 입력:
- 링크 제목
- 링크 URL

선택 입력:
- 아이콘 또는 썸네일 이미지

지원 기능:
- 링크 추가
- 링크 조회
- 링크 수정
- 링크 삭제
- 링크 순서 변경
- 링크 활성화 및 비활성화

링크 추가와 수정은 저장 버튼을 눌러 확정한다.

사용자별 링크 수에 별도의 제품 정책상 최대 제한은 두지 않는다.

### FR-08. 링크 URL 검증

- URL 필수 입력
- 올바른 절대 URL 형식 검사
- HTTP 및 HTTPS 프로토콜만 허용
- javascript:, data:, file: 등 위험한 프로토콜 차단
- 클라이언트와 데이터 저장 처리 단계 모두에서 검증

외부 사이트의 실제 접속 가능 여부를 서버에서 검사하는 기능은 제공하지 않는다.

### FR-09. 외부 링크 열기

모든 외부 링크는 새 탭에서 연다.

적용 속성:
- target="_blank"
- rel="noopener noreferrer"

### FR-10. 링크 삭제

1. 사용자가 삭제 버튼 클릭
2. 삭제 확인 모달 표시
3. 영구 삭제 및 복구 불가 안내
4. 사용자가 최종 확인
5. 링크와 관련 클릭 통계 삭제
6. 삭제 결과 화면 반영

휴지통이나 삭제 복구 기능은 제공하지 않는다.

### FR-11. 링크 활성화

각 일반 링크는 활성화 상태를 가진다.

활성화:
- 공개 페이지에 표시
- 방문자가 클릭 가능
- 클릭 통계 집계

비활성화:
- 공개 페이지에서 숨김
- 신규 클릭 집계 중단
- 기존 클릭 통계 보존
- 소유자 관리 및 통계 화면에는 표시

다시 활성화하면 기존 클릭 통계를 유지한다.

### FR-12. 링크 순서 변경

- 드래그 앤 드롭 지원
- 모바일 터치 지원
- 드래그 완료 즉시 자동 저장
- 새로고침 후 순서 유지
- 저장 중 상태 표시
- 저장 실패 시 이전 순서 복구 및 오류 안내

## 8. SNS 아이콘 관리

### FR-13. SNS 링크 등록

일반 링크와 SNS 아이콘은 별도로 관리한다.

사용자는 SNS 플랫폼을 선택하고 해당 URL을 입력한다.

지원 플랫폼 예시:
- Instagram
- YouTube
- GitHub
- TikTok
- X

플랫폼 선택 시 해당 SNS 아이콘이 자동으로 지정된다.

지원 기능:
- SNS 링크 등록
- SNS 링크 수정
- SNS 링크 삭제
- SNS 링크 목록 조회

SNS URL에도 HTTP·HTTPS 검증 정책을 적용한다.

외부 SNS 링크도 새 탭에서 연다.

### FR-14. SNS 아이콘 순서

- 드래그 앤 드롭으로 순서 변경
- 일반 링크와 독립적인 정렬 순서
- 드래그 완료 즉시 자동 저장
- 새로고침 후 순서 유지
- 모바일 터치 지원
- 저장 실패 시 이전 순서 복구

사용자 지정 SNS 아이콘 이미지 업로드는 필수 기능에 포함하지 않는다.

## 9. 공개 프로필 페이지

### FR-15. 공개 페이지 구성

표시 요소:
- 프로필 사진
- 표시 이름
- 자기소개
- SNS 아이콘 영역
- 활성화된 일반 링크 목록

공개 페이지는 비로그인 사용자도 접근할 수 있다.

다른 사용자의 수정 및 삭제 기능은 노출하거나 허용하지 않는다.

존재하지 않는 username으로 접근하면 찾을 수 없음 페이지를 표시한다.

### FR-16. URL 공유

소유자와 방문자 모두 개인 페이지 URL을 복사하고 공유할 수 있다.

공유 기능:
- URL 복사
- 공유 버튼
- 복사 완료 피드백

## 10. 디자인 커스터마이징

### FR-17. 디자인 시스템

신규 UI는 기존 공통 컴포넌트를 기반으로 한다. 제품 색상과 화면 스타일의 실제 기준은 [통합 기준](PRODUCT_ALIGNMENT.md) 및 `globals.css`, `profile-design.ts`이며 `design.md`는 초기 Toss 참고 자료다.

기본 방향:
- 크림 계열 기본 배경
- 라임 강조색과 차콜 텍스트, 코랄 보조색
- 간결한 구성
- 명확한 버튼
- 일관된 간격
- 깔끔한 카드와 폼

Toss의 로고나 독점 디자인 자산을 그대로 복제하지 않는다.

### FR-18. 테마 설정

사용자는 기본 제공 테마를 선택하거나 직접 색상을 지정할 수 있다.

설정 항목:
- 기본 테마
- 배경색
- 버튼색
- 텍스트색

설정 중에는 실시간 미리보기에 반영한다.

저장 버튼을 누르면 실제 공개 페이지에 반영한다.

배경 이미지, 글꼴, 버튼 모양 등의 고급 편집 기능은 필수 범위가 아니다.

### FR-19. 실시간 미리보기

다음 항목을 지원한다.
- 프로필 수정 미리보기
- 일반 링크 수정 미리보기
- 테마 변경 미리보기

미리보기는 저장 전 수정 내용을 표시할 수 있으나, 실제 공개 페이지는 저장된 데이터만 사용한다.

- 일반 링크별 누적 클릭 수 표시
- 전체 일반 링크 누적 클릭 수 표시
- 동일 방문자의 반복 클릭도 각각 집계
- 고유 방문자 수는 추적하지 않음
- 소유자 관리 화면에서 확인

### FR-21. 통계 보존 및 삭제

링크 비활성화:
- 기존 클릭 통계 유지
- 새 클릭 집계 중단

링크 재활성화:
- 기존 통계 유지
- 새 클릭 집계 재개

링크 삭제:
- 해당 링크 클릭 통계 영구 삭제
- 전체 클릭 합계에서도 삭제된 링크의 클릭 수 제외

클릭 수 증가는 신뢰할 수 있는 서버 처리와 원자적 데이터 갱신을 사용한다.

---

## 12. OG 메타데이터

### FR-22. 개인별 공유 미리보기

사용자가 공개 프로필 URL을 메신저나 SNS에 공유할 때 다음 정보가 표시되도록 한다.

- OG 제목
- OG 설명
- OG 이미지

사용자별 프로필 정보를 기준으로 동적 메타데이터를 생성한다.

로그인하지 않은 SNS 미리보기 수집기에서도 접근 가능해야 한다.

프로필 이미지가 없는 경우 사용할 기본 OG 이미지도 마련한다.

---

## 13. 계정 탈퇴

### FR-23. 계정 삭제

사용자가 계정 탈퇴를 요청하면 확인 절차를 거친다.

삭제 대상:
- Firebase Authentication 계정
- Firestore 프로필
- Firestore 일반 링크
- SNS 링크
- 클릭 통계
- Firebase Storage 프로필 이미지
- Firebase Storage 링크 이미지
- username 연결

삭제 완료 후 기존 공개 페이지는 제공하지 않는다.

기존 username은 즉시 재사용 가능하다.

부분 삭제나 권한 오류로 데이터가 남지 않도록 신뢰할 수 있는 서버 측 삭제 절차를 사용한다.

## 14. 화면 정보 구조(IA)

```text
MyLink
│
├── 공개 영역
│   ├── 서비스 소개 / 시작하기
│   ├── Google 로그인
│   ├── 최초 온보딩
│   └── 개인 공개 프로필
│
└── 사용자 관리 영역
    ├── 대시보드
    ├── 프로필 관리
    ├── 일반 링크 관리
    ├── SNS 링크 관리
    ├── 디자인 설정
    ├── 클릭 통계
    └── 계정 설정 / 탈퇴
```

권장 경로:

| 화면 | 경로 예시 |
|---|---|
| 시작 | / |
| 로그인 | /login |
| 온보딩 | /onboarding |
| 대시보드 | /dashboard |
| 프로필 관리 | /dashboard/profile |
| 링크 및 SNS 관리 | /dashboard/links |
| 디자인 설정 | /dashboard/design |
| 통계 | /dashboard/stats |
| 계정 설정 | /dashboard/settings |
| 개인 공개 페이지 | /:username |

위 경로는 목표 IA 예시로 현재 실제 라우트와 다릅니다. 현재는 `/`(랜딩/로그인 후 관리), `/mypage`(탭형 관리), `/stats`, `/{username}`를 사용합니다. 실제·목표 경로 대조는 [통합 기준](PRODUCT_ALIGNMENT.md)을 참조합니다.

## 15. 권장 데이터 구조

### users

사용자 기본 정보 및 테마 설정

```text
users/{uid}
  displayName
  username
  bio
  photoURL
  theme
  createdAt
  updatedAt
```

### usernames

고유 username 예약 및 사용자 연결

```text
usernames/{username}
  uid
  createdAt
```

username 생성 및 변경은 동시 요청에서도 중복되지 않도록 트랜잭션으로 처리한다.

### links

사용자별 일반 링크

```text
users/{uid}/links/{linkId}
  title
  url
  imageURL
  icon
  enabled
  sortOrder
  clickCount
  createdAt
  updatedAt
```

### socialLinks

사용자별 SNS 아이콘

```text
users/{uid}/socialLinks/{socialId}
  platform
  url
  sortOrder
  createdAt
  updatedAt
```

위 데이터 모델은 목표 설계 예시다. **실제 Firestore 경로와 필드는 [통합 기준](PRODUCT_ALIGNMENT.md)의 데이터 구조를 우선 확인**한다. 특히 SNS는 별도 컬렉션이 아닌 프로필의 `socialLinks` 배열이며, 링크는 `isActive`, `isFeatured`, `thumbnailUrl`, `group`을 사용한다. 요구사항은 유지하되 코드와 필드명을 혼동하지 않는다.

## 18. 단계별 개발 계획

### Phase 1. MVP

구현 기능:
- Google 로그인
- 사용자 온보딩
- username 생성 및 중복 검사
- 프로필 CRUD
- 일반 링크 CRUD
- 개인 공개 URL
- 공개 프로필 페이지
- 기본 보안 및 입력 검증

완료 기준:
- 사용자가 Google 계정으로 가입할 수 있다.
- 자신만의 username을 등록할 수 있다.
- 프로필과 링크를 관리할 수 있다.
- 방문자가 로그인 없이 공개 페이지를 볼 수 있다.
- 다른 사용자의 데이터를 수정할 수 없다.

### Phase 2. 사용자 경험 확장

구현 기능:
- 일반 링크 활성화 및 비활성화
- 일반 링크 순서 드래그 앤 드롭
- SNS 링크 등록·수정·삭제
- SNS 아이콘 표시 및 순서 변경
- 기본 테마 선택
- 배경색·버튼색·텍스트색 변경
- 실시간 미리보기
- 전체 반응형 및 모바일 터치 지원

완료 기준:
- 링크와 SNS 순서 변경이 자동 저장된다.
- 비활성 링크가 공개 화면에서 숨겨진다.
- 색상 및 테마 변경이 저장 후 공개 페이지에 반영된다.
- 미저장 변경은 공개 페이지에 나타나지 않는다.

### Phase 3. 서비스 완성

구현 기능:
- 링크별 클릭 통계
- 전체 클릭 통계
- 반복 클릭 집계
- 개인 페이지 URL 공유
- 동적 OG 메타데이터
- 계정 탈퇴 및 데이터 삭제
- Vercel 배포
- 통합 테스트

완료 기준:
- 링크 클릭 수가 정확하게 집계된다.
- SNS 공유 시 개인별 미리보기가 생성된다.
- 계정 탈퇴 시 관련 데이터가 정리된다.
- 배포된 URL에서 정상적으로 서비스가 작동한다.

## 21. 프로젝트 개발 원칙

1. 기존 프로젝트의 코드와 구조를 우선 분석한다.
2. 이미 구현한 기능은 불필요하게 재작성하지 않는다.
3. 확정한 요구사항을 임의로 축소하거나 변경하지 않는다.
4. Phase 1 → Phase 2 → Phase 3 순서로 개발한다.
5. 각 단계 구현 후 기능을 검증한다.
6. Firebase 보안 규칙을 반드시 적용한다.
7. GitHub에 단계별 변경 사항을 기록한다.
8. 최종 목표는 Vercel에 배포된 정상 동작 서비스다.
9. 미구현 기능을 완료했다고 보고하지 않는다.
10. 사용자 시나리오 및 와이어프레임 문서와 일관성을 유지한다.
