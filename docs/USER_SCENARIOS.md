# MyLink 사용자 시나리오 (USER SCENARIOS)

> **최종 목표 사용자 흐름**을 정의합니다. 현재 구현과 다른 절차(별도 온보딩, 독립 대시보드, SNS 드래그 정렬, 계정 탈퇴 등)는 [정합성 점검표](PRODUCT_ALIGNMENT.md)에서 미구현·부분 구현으로 관리합니다. 현재 구현됐다는 뜻이 아닙니다.

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 서비스 | MyLink |
| 문서 | 사용자 시나리오 |
| 기준 문서 | PRD.md, PRODUCT_ALIGNMENT.md(구현 현황) |
| 개발 목표 | Phase 1~3 전체 기능 구현 |
| 사용자 유형 | 비로그인 방문자, 로그인 사용자 |
| 목적 | 실제 사용자 행동을 기준으로 화면 흐름과 기능 동작 정의 |

본 문서는 사용자가 MyLink에 접속해 회원가입, 프로필 설정, 링크 관리, 공개 페이지 공유, 통계 확인, 계정 탈퇴를 수행하는 과정을 설명한다.

### 사용자 유형

**사용자 A: 페이지 소유자**

- Google 계정으로 가입 및 로그인한다.
- 자신의 프로필과 링크를 관리한다.
- 공개 URL을 공유한다.
- 클릭 통계를 확인한다.
- 자신의 계정을 삭제할 수 있다.

**사용자 B: 방문자**

- Google 로그인 없이 공개 페이지를 방문한다.
- 활성화된 링크를 열람한다.
- SNS 아이콘을 클릭한다.
- 페이지 URL을 복사하고 공유한다.
- 다른 사용자의 데이터를 수정할 수 없다.

## SC-01. Google 로그인 및 최초 회원가입

**사용자:** 최초 방문 사용자  
**개발 단계:** Phase 1

### 목적

Google 계정으로 로그인하고 자신만의 MyLink 페이지를 생성한다.

### 사전 조건

- 사용자가 로그인하지 않은 상태다.
- Google 계정을 가지고 있다.

### 정상 흐름

1. 사용자가 MyLink 시작 페이지에 접속한다.
2. `Google로 시작하기` 버튼을 클릭한다.
3. Google 계정 인증을 진행한다.
4. Firebase Authentication이 인증 결과를 처리한다.
5. 신규 사용자임을 확인하면 온보딩 화면으로 이동한다.
6. 사용자가 고유 아이디(username)를 입력한다.
7. 서비스가 아이디 형식과 중복 여부를 검사한다.
8. 사용자가 표시 이름을 입력한다.
9. 선택적으로 프로필 사진과 자기소개를 설정한다.
10. 사용자가 설정 완료 버튼을 클릭한다.
11. 사용자 프로필이 Firestore에 저장된다.
12. 사용자 고유 URL이 생성된다.
13. 대시보드로 이동한다.

### 예외 흐름

- Google 인증 취소: 로그인 화면 유지
- 인증 실패: 오류 메시지 표시 및 재시도 제공
- username 형식 오류: 입력 규칙 안내
- username 중복: 다른 아이디 입력 요청
- username 동시 등록 충돌: 저장 실패 처리 및 재입력 안내
- 필수 입력 누락: 설정 완료 차단
- 데이터 저장 실패: 입력값 유지 및 재시도 가능

### 완료 조건

- 사용자 계정이 생성된다.
- 고유 username이 예약된다.
- 개인 공개 URL에 접근할 수 있다.

## SC-02. 기존 사용자 로그인 및 로그아웃

**사용자:** 기존 가입 사용자  
**개발 단계:** Phase 1

### 정상 흐름

1. 사용자가 MyLink에 접속한다.
2. Google 로그인 버튼을 클릭한다.
3. Firebase Authentication으로 인증한다.
4. 기존 사용자 프로필을 확인한다.
5. 온보딩을 건너뛰고 대시보드로 이동한다.
6. 사용자가 로그아웃 버튼을 클릭하면 인증 상태가 해제된다.
7. 보호된 관리 페이지 접근 시 다시 로그인이 필요하다.

### 예외 흐름

- 인증 실패: 오류 안내
- 프로필 데이터가 불완전함: 온보딩 완료 여부를 확인하고 필요한 설정 화면으로 이동
- 로그아웃 후 관리 URL 접근: 로그인 화면으로 이동

### 완료 조건

- 기존 사용자는 정상 로그인 및 로그아웃할 수 있다.
- 로그인하지 않은 사용자는 관리 기능에 접근할 수 없다.

## SC-03. 프로필 정보 등록 및 수정

**사용자:** 로그인 사용자  
**개발 단계:** Phase 1, 미리보기는 Phase 2

### 목적

공개 페이지에 표시할 자신의 정보를 관리한다.

### 정상 흐름

1. 사용자가 대시보드에서 `프로필 관리`로 이동한다.
2. 현재 프로필 사진, 표시 이름, 자기소개를 확인한다.
3. 표시 이름이나 자기소개를 수정한다.
4. 필요하면 프로필 이미지를 업로드한다.
5. 변경 내용이 실시간 미리보기에 표시된다.
6. 사용자가 `저장` 버튼을 클릭한다.
7. 입력 검증을 통과하면 Firestore에 반영한다.
8. 저장 성공 메시지를 표시한다.
9. 공개 페이지에서도 새 프로필 정보가 보인다.

### 프로필 이미지 조건

- JPG, PNG, WebP 지원
- 파일당 최대 5MB
- Firebase Storage 저장
- 정사각형 영역에 이미지 표시
- 이미지 비율 왜곡 방지

### 예외 흐름

- 지원하지 않는 이미지 형식: 업로드 거부
- 5MB 초과: 업로드 거부 및 제한 안내
- 저장 실패: 수정 내용 유지 및 오류 표시
- 저장 전 페이지 이동: 미저장 변경 안내
- 다른 사용자 프로필 수정 시도: 권한 거부

### 완료 조건

- 저장된 내용만 실제 공개 페이지에 반영된다.
- 저장하지 않은 변경 내용은 미리보기에만 표시된다.

## SC-04. 일반 링크 추가

**사용자:** 로그인 사용자  
**개발 단계:** Phase 1

### 목적

자신의 공개 페이지에 외부 사이트 링크를 등록한다.

### 정상 흐름

1. 사용자가 `링크 관리` 화면으로 이동한다.
2. `링크 추가` 버튼을 클릭한다.
3. 링크 제목을 입력한다.
4. 링크 URL을 입력한다.
5. 선택적으로 아이콘 또는 썸네일 이미지를 설정한다.
6. 입력 결과를 미리보기에서 확인한다.
7. 사용자가 `저장` 버튼을 클릭한다.
8. URL과 필수 입력값을 검증한다.
9. 검증 성공 시 Firestore에 링크를 저장한다.
10. 새 링크가 관리 목록 및 공개 페이지에 표시된다.

### 입력 규칙

필수:
- 링크 제목
- 링크 URL

선택:
- 아이콘 또는 썸네일 이미지

URL:
- 올바른 절대 URL이어야 한다.
- `http://`와 `https://`만 허용한다.
- `javascript:`, `data:`, `file:` 등은 차단한다.

### 예외 흐름

- 제목 미입력: 저장 불가
- URL 미입력: 저장 불가
- URL 형식 오류: 안내 메시지 표시
- 위험한 URL 프로토콜: 저장 거부
- 저장 실패: 입력값 유지
- 인증되지 않은 추가 요청: 권한 거부

### 완료 조건

- 소유자가 링크를 등록할 수 있다.
- 저장된 링크가 공개 페이지에 표시된다.

## SC-05. 일반 링크 수정

**사용자:** 로그인 사용자  
**개발 단계:** Phase 1, 미리보기는 Phase 2

### 정상 흐름

1. 사용자가 `링크 관리` 화면을 연다.
2. 수정할 링크의 `편집` 버튼을 클릭한다.
3. 기존 제목과 URL이 입력창에 표시된다.
4. 제목, URL 또는 이미지 정보를 변경한다.
5. 수정 결과를 미리보기에서 확인한다.
6. 사용자가 `저장` 버튼을 클릭한다.
7. 입력 검증 및 소유권 검사를 진행한다.
8. Firestore에 수정 내용을 반영한다.
9. 저장 성공 메시지를 표시한다.

### 예외 흐름

- 잘못된 URL: 저장 거부
- 필수 입력값 누락: 저장 거부
- 존재하지 않는 링크: 오류 표시
- 다른 사용자 링크 수정 시도: 권한 거부
- 저장 실패: 입력값 유지

### 완료 조건

- 저장 전에는 기존 공개 링크가 유지된다.
- 저장 후 수정된 링크가 공개 페이지에 반영된다.

## SC-06. 일반 링크 삭제

**사용자:** 로그인 사용자  
**개발 단계:** Phase 1

### 정상 흐름

1. 사용자가 링크 관리 화면에서 삭제할 링크를 선택한다.
2. `삭제` 버튼을 클릭한다.
3. 삭제 확인 모달이 표시된다.
4. 모달에서 삭제 대상과 복구 불가 안내를 확인한다.
5. 사용자가 `삭제하기`를 클릭한다.
6. 소유권을 확인한 후 해당 링크를 영구 삭제한다.
7. 관련 클릭 통계도 삭제된다.
8. 링크 목록과 전체 클릭 합계가 갱신된다.
9. 삭제 완료 메시지를 표시한다.

### 예외 흐름

- `취소` 선택: 삭제하지 않고 모달 닫기
- 삭제 중 오류: 링크 유지 및 오류 안내
- 권한 없는 삭제 요청: 거부
- 이미 삭제된 링크: 적절한 오류 안내

### 완료 조건

- 삭제한 링크는 공개 페이지에서 사라진다.
- 해당 링크의 클릭 기록이 삭제된다.
- 휴지통 및 복구 기능은 없다.

## SC-07. 링크 순서 변경 및 활성화 관리

**사용자:** 로그인 사용자  
**개발 단계:** Phase 2

### 정상 흐름: 순서 변경

1. 사용자가 링크 관리 화면에 접속한다.
2. 링크 목록에서 이동할 항목을 선택한다.
3. 드래그 앤 드롭으로 위치를 변경한다.
4. 드래그가 완료되면 새 순서를 자동 저장한다.
5. 저장 완료 후 새 순서를 표시한다.
6. 페이지를 새로고침해도 순서가 유지된다.

모바일에서는 터치 조작을 지원한다.

### 정상 흐름: 활성화 변경

1. 사용자가 링크의 활성화 스위치를 변경한다.
2. 비활성화하면 공개 페이지에서 해당 링크가 숨겨진다.
3. 기존 클릭 통계는 유지된다.
4. 비활성화 중 신규 클릭은 집계하지 않는다.
5. 재활성화하면 링크가 다시 표시된다.
6. 기존 클릭 수에 이후 클릭 수가 누적된다.

### 예외 흐름

- 순서 저장 실패: 기존 순서 복구 및 오류 표시
- 활성화 상태 변경 실패: 이전 상태 유지 또는 복구
- 다른 사용자 링크 접근: 권한 거부

### 완료 조건

- 링크 순서와 활성화 상태가 저장된다.
- 비활성 링크는 방문자에게 표시되지 않는다.

## SC-08. SNS 아이콘 등록 및 관리

**사용자:** 로그인 사용자  
**개발 단계:** Phase 2

### 목적

SNS 플랫폼별 아이콘을 공개 프로필에 표시한다.

### 정상 흐름

1. 사용자가 `링크 관리` 화면의 SNS 영역으로 이동한다.
2. `SNS 추가` 버튼을 클릭한다.
3. 지원하는 SNS 플랫폼을 선택한다.
4. 해당 플랫폼의 URL을 입력한다.
5. URL 형식과 프로토콜을 검증한다.
6. 사용자가 저장 버튼을 클릭한다.
7. SNS 정보가 Firestore에 저장된다.
8. 플랫폼에 해당하는 아이콘이 자동 설정된다.
9. 공개 페이지 SNS 아이콘 영역에 표시된다.

### SNS 순서 변경

1. 사용자가 SNS 목록을 확인한다.
2. 아이콘 항목을 드래그해 순서를 변경한다.
3. 변경 완료 시 자동 저장한다.
4. 새로고침 후에도 순서를 유지한다.

### 예외 흐름

- 플랫폼 미선택: 등록 불가
- URL 미입력: 등록 불가
- 위험한 프로토콜: 등록 거부
- 저장 실패: 기존 상태 유지
- 정렬 실패: 이전 순서 복구

### 완료 조건

- SNS 아이콘과 URL이 연결된다.
- SNS 아이콘 순서가 독립적으로 관리된다.
- 클릭하면 외부 SNS 페이지가 새 탭에서 열린다.

## SC-09. 디자인 및 테마 변경

**사용자:** 로그인 사용자  
**개발 단계:** Phase 2

### 목적

자신의 공개 페이지 디자인을 변경한다.

### 정상 흐름

1. 사용자가 `디자인 설정` 화면으로 이동한다.
2. 기본 제공 테마를 선택하거나 색상을 직접 지정한다.
3. 배경색을 변경한다.
4. 버튼색을 변경한다.
5. 텍스트색을 변경한다.
6. 변경된 디자인이 실시간 미리보기에 나타난다.
7. 사용자가 `저장` 버튼을 클릭한다.
8. 테마 설정을 Firestore에 저장한다.
9. 공개 프로필에 새 디자인이 적용된다.

### 예외 흐름

- 저장 실패: 이전 공개 디자인 유지
- 미저장 변경 후 이동: 확인 안내
- 읽기 어려운 색상 조합: 대비 확인을 위한 안내 또는 검증 제공

### 완료 조건

- 저장된 디자인만 방문자에게 공개된다.
- 모바일과 데스크톱에서 일관되게 표시된다.

## SC-10. 비로그인 방문자의 공개 페이지 이용

**사용자:** 비로그인 방문자  
**개발 단계:** Phase 1, SNS 및 공유 기능은 후속 단계

### 정상 흐름

1. 방문자가 공유받은 MyLink URL을 연다.
2. 서비스가 URL에 포함된 username을 조회한다.
3. 해당 사용자의 공개 프로필을 불러온다.
4. 프로필 사진, 표시 이름, 자기소개를 표시한다.
5. SNS 아이콘 목록을 표시한다.
6. 활성화된 일반 링크를 순서대로 표시한다.
7. 방문자가 일반 링크를 클릭한다.
8. 외부 사이트가 새 탭에서 열린다.
9. 방문자가 원래 MyLink 페이지로 돌아올 수 있다.

### 예외 흐름

- username이 존재하지 않음: 404 또는 찾을 수 없음 화면
- 해당 사용자가 탈퇴함: 공개 페이지 제공 중단
- 비활성 링크: 목록에 표시하지 않음
- 데이터 로딩 실패: 오류 또는 재시도 안내

### 완료 조건

- 방문자는 로그인 없이 공개 페이지를 이용할 수 있다.
- 방문자에게 관리 기능이 제공되지 않는다.

## SC-11. 개인 URL 복사 및 공유

**사용자:** 로그인 사용자 또는 비로그인 방문자  
**개발 단계:** Phase 3

### 정상 흐름

1. 사용자가 개인 공개 페이지에서 `공유` 버튼을 클릭한다.
2. 서비스가 해당 페이지의 공개 URL을 확인한다.
3. URL 복사 또는 기기 공유 기능을 제공한다.
4. 사용자가 복사 버튼을 누른다.
5. URL이 클립보드에 복사된다.
6. 복사 완료 메시지가 표시된다.
7. 사용자가 메신저나 SNS에 URL을 공유한다.
8. 공유 플랫폼에서 개인별 OG 미리보기를 표시할 수 있다.

### 예외 흐름

- 클립보드 접근 실패: URL 직접 복사 대안 제공
- 공유 API 미지원: URL 복사 기능 제공
- OG 수집 실패: URL 자체로 접근 가능

### 완료 조건

- 공유된 URL로 비로그인 방문자가 공개 페이지에 접근할 수 있다.
- 플랫폼이 OG를 지원하면 개인별 제목·설명·이미지를 제공한다.

## SC-12. 링크 클릭 통계 확인

**사용자:** 로그인 사용자  
**개발 단계:** Phase 3

### 정상 흐름

1. 사용자가 대시보드에서 `통계` 메뉴를 클릭한다.
2. 서비스가 소유자의 링크별 클릭 수를 조회한다.
3. 전체 누적 클릭 수를 표시한다.
4. 링크별 누적 클릭 수를 표시한다.
5. 비활성화된 링크의 기존 클릭 수도 표시한다.
6. 사용자가 다시 활성화한 링크는 이전 수치부터 계속 집계된다.

### 집계 정책

- 링크를 클릭할 때마다 1회 집계한다.
- 같은 방문자가 반복 클릭해도 각각 집계한다.
- 고유 방문자 수는 계산하지 않는다.
- 비활성 링크는 신규 클릭을 집계하지 않는다.
- 삭제된 링크의 클릭 수는 통계에서 제거한다.

### 예외 흐름

- 통계 조회 실패: 오류 및 재시도 안내
- 링크가 하나도 없음: 빈 상태 표시
- 비로그인 사용자의 통계 접근: 로그인 요청
- 타인 통계 접근: 권한 거부

### 완료 조건

- 소유자는 링크별·전체 누적 클릭 수를 확인할 수 있다.
- 통계 접근은 소유자에게만 허용된다.

---

## SC-13. Username 변경

**사용자:** 로그인 사용자  
**개발 단계:** Phase 1 기반 기능, 설정 화면에서 제공

### 정상 흐름

1. 사용자가 계정 설정 화면에 접속한다.
2. 현재 username을 확인한다.
3. 새로운 username을 입력한다.
4. 서비스가 입력 형식 및 예약어를 검사한다.
5. 새로운 username의 중복 여부를 검사한다.
6. 사용자가 변경을 확정한다.
7. 서버가 username 변경을 원자적으로 처리한다.
8. 새 URL이 활성화된다.
9. 기존 URL은 더 이상 기존 사용자의 페이지에 연결되지 않는다.
10. 변경 완료 안내와 새 URL을 표시한다.

### 예외 흐름

- 형식 오류: 변경 거부
- 예약어 사용: 변경 거부
- 이미 사용 중: 변경 거부
- 동시 등록 충돌: 변경 거부 및 재시도 안내
- 변경 처리 실패: 기존 username 유지

### 중요한 정책

- 이전 username은 변경 완료 후 즉시 다른 사람이 재사용할 수 있다.
- 기존 공유 링크가 나중에 다른 사용자의 프로필을 표시할 수 있다.
- 변경 전에 이러한 위험을 안내한다.

### 완료 조건

- username 변경 후 새로운 URL로 접근할 수 있다.
- 중복 username이 발생하지 않는다.

## SC-14. 계정 탈퇴 및 데이터 영구 삭제

**사용자:** 로그인 사용자  
**개발 단계:** Phase 3

### 목적

서비스 계정과 관련 데이터를 삭제한다.

### 정상 흐름

1. 사용자가 계정 설정 화면으로 이동한다.
2. `계정 탈퇴`를 선택한다.
3. 삭제 대상과 복구 불가 안내를 확인한다.
4. 필요하면 재인증을 수행한다.
5. 사용자가 최종 삭제를 확정한다.
6. 서버 측 계정 삭제 프로세스를 실행한다.
7. 프로필·일반 링크·SNS 링크·통계·업로드 이미지 등을 삭제한다.
8. 사용자 인증 계정을 삭제한다.
9. username 예약을 해제한다.
10. 공개 페이지 접근을 중단한다.
11. 탈퇴 처리 결과를 표시한다.

### 삭제 대상

- Firebase Authentication 계정
- Firestore 사용자 프로필
- 일반 링크
- SNS 링크
- 클릭 통계
- Storage 프로필 이미지
- Storage 링크 이미지
- username 연결 정보

### 예외 흐름

- 취소 선택: 데이터 유지
- 재인증 실패: 삭제 진행 차단
- 중간 단계 실패: 삭제 상태를 관리하고 안전하게 재시도 또는 복구 처리
- 삭제 완료 후 로그인 시도: 신규 가입 절차 진행

### 완료 조건

- 사용자 관련 데이터가 삭제된다.
- 기존 공개 페이지는 비활성화된다.
- username은 다시 등록 가능해진다.

## 3. 공통 UX 원칙

### 3.1 저장 방식

- 프로필 추가·수정: 저장 버튼
- 일반 링크 추가·수정: 저장 버튼
- SNS 링크 등록·수정: 저장 버튼
- 디자인 및 테마 변경: 저장 버튼
- 일반 링크 순서 변경: 자동 저장
- SNS 아이콘 순서 변경: 자동 저장

### 3.2 피드백

모든 주요 작업에는 적절한 상태 피드백을 제공한다.

- 로딩
- 저장 중
- 저장 완료
- 저장 실패
- 삭제 완료
- 복사 완료
- 빈 목록
- 접근 권한 없음

### 3.3 반응형

모바일·태블릿·데스크톱에서 모든 주요 기능을 사용할 수 있어야 한다.

### 3.4 접근 제어

- 공개 페이지는 로그인 없이 열람 가능
- 프로필 및 링크 변경은 소유자만 가능
- 개인 통계는 소유자만 확인 가능
- 다른 사용자 데이터 변경 시도는 서버에서 거부
